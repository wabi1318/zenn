# Vue Fes Japan とは

https://vuefes.jp/2025/

Vue Fes Japan は、日本最大級の Vue.js に関するカンファレンスです。
Vue.js だけでなく、Vite, Rolldown などのツールチェーンやエコシステムに関する知見や動向を共有する場であり、国内外の著名なスピーカーによる講演やハンズオンセッション等非常に魅力的なコンテンツを提供してくださっています 🙏

最近は Vue.js を使用していませんが、Vue.js, Vite 作者の Evan You 氏、元 React コアメンバー/元 Bluesky コアメンバーの Dan Abramov 氏、Svelte, Vite コアチームの dominikg 氏らが登壇されるとのことで申し込みました。

全セッション内でスクリーン上にリアルタイム日英同時翻訳が表示されており、英語力カスな私にはかなり助かりました。日本語 → 英語同時翻訳はままありますが、英語 → 日本語翻訳は珍しいですね。実際、参加者にも英語話者が結構いた印象でした。

## キーノート by Evan You 氏

- Vue 3.6 について
  - [Alien Signals](https://github.com/stackblitz/alien-signals) を新しいリアクティビティエンジンとして導入
  - Vapor Mode 対応（コンパイラの実装により仮想 DOM を使用しないモード）
- void(0)のツール開発について
  - JS で作られたツールは性能に限界がある（単一スレッドで並列化が困難）。ネイティブ実装（主に Rust）に移行するべき
  - そこで Rust ベースの高速なツール群を開発中（Oxc 系）。
- Vite+について
  - https://viteplus.dev/
  - 統合された Web 開発ツールチェーン
  - Vite の後継として位置づけ
  - AI と開発ツールの統合を目指す
  - 有料、現在公開されてる OSS(Vite、Vitest、Rolldown、Oxc など)は MIT ライセンスのもとで無料のままらしい

Signals, Zero-Runtime, ネイティブ実装対応など最近のフロントエンドフレームワークのトレンドにノリに乗った発表でした。
[Oxc 系](https://oxc.rs/)は Rust 実装のツール群、かつ共通の AST 形式で連携するらしくアツいですね。もういくつかリリースされているものがあるようなので、個人的に使ってみたいなと思いました。とくに Oxlint の開発にあたっては TS チームと連携しているらしく素敵ですね。

## フレームワークを超えて ── 次の 10 年のウェブを築く by Daniel Roe 氏

https://rfihabsudkpoqozp.public.blob.vercel-storage.com/slides/2025-09-20-wts-beyond-framework.pdf

- 重要なのは、Vue や Nuxt などの道具だけでなく、人間の判断や審美眼、そして職人（エンジニア）の技術
- 枠組みによって自分のアイデンティティを決めつけるのは避けるべき。道具はあくまで技術を助けるためのものに過ぎない。
- Web は急速に進化し、学び続けることは欠かせないが、取り残される不安に囚われすぎないのが大事。何よりも大切なのは価値を届けること
- フレームワークは避けられないものであり、有益、共有のフレームワークを採用しないと、自社でフレームワークを一から作り直すことになる
- フレームワークはベストプラクティスをまとめ、障害を減らし、アイデアの実現までのスピードを加速する

フレームワークはベストプラクティスの集積、というのに非常に共感しました。やはり使ってみると便利ですし、他の開発者のこうなったらいいなポイントを先に実装し使えるようにしてくれているんですよね、、、
手元の端末からリアクションを送れる仕掛けがされているのが非常に印象的なセッションで、面白かったです。最後に Nuxt v4.2.0 がライブマージされてびっくりしました。

## フロントエンドの未来を語る ── React/Vue.js/Svelte が見据える次の 10 年 by Evan You 氏、Dan Abramov 氏、dominikg 氏、Kia King Ishii 氏

- AI コーディングの使用
  - Evan 氏: Vue.js 開発では AI 使用は限定的（ハルシネーションが嫌なので手書きコーディングを重視している）。一方で新規（Rust 系など）のプロジェクトや不具合修正では AI を広く活用している
  - dominikg 氏: 信頼性の観点から AI コーディングを全く使用しない
  - Dan 氏: サイドプロジェクトで vibe coding を試した。手戻りはあるが未知のドメインでも短期で形にできる
  - 「Vibe coding」と「AI に支援されたエンジニアリング」は、制御の度合いというスペクトラム上に存在
    - Vibe coding：AI が主導するもので、探究には適しているが、雑な結果を生みやすい
    - AI に支援されたエンジニアリングとは、計画を優先し反復的に議論を行い、Linting、型付け、テストで安全策を設ける手法
    - 効果的な「AI の管理」とは、優れたエンジニアリングの管理と同様といえる。計画を立て、範囲を明確にし、成果物を確認し、品質を徹底すること
- AI の役割
  - 外部委託的に任せる or 協働者として並走させる。議論は「人を拡張する協働者」寄り？
  - AI による無制限な機能追加が、製品の独自性を弱めてしまう。核心となる製品ビジョンについて、人間の判断が依然として欠かせない
- AI 時代のフレームワーク・ツールの設計
  - フレームワーク設計は今後、AI を前提にせざるを得ない
  - 読みやすいドキュメントは AI とも相性がいい
  - 大規模なアップグレードでは、明確な変更リストを必ず提供する必要
  - エージェントが処理・計測・修正できるよう、コンポーネントの props への MCP のようなアクセスやスタックトレース、ファイルの差分など内部情報の確認機能を提供する API やツールの設計が必要
  - 宣言的で合成可能なアーキテクチャは、全体を壊すことなく局所的な変更を可能にするため、AI や人間にとって扱いやすいもの
  - Linting／型チェック／テストなどの共通基盤ツール群とフレームワークが密に結びつくことが、AI 支援下での正確さ・信頼性を高める
- エンジニア（特に新人エンジニア）に向けて
  - これからのフロントエンドエンジニアには、急速に変化する技術への適応、好奇心、学習力に加えて、AI 生成コードのデバッグと整理能力が求められる。基礎の理解は依然として大きな差別化要因となる

dominikg 氏が「AI は使用しない」と言い切っていて非常に硬派な印象を受けましたが、一方で AI ツールのためにも明確で分かりやすいドキュメントが重要と言っていて、ここは非常に共感するところでした。確かに Svelte は早くから llms.txt を整備していて、AI にコーディングさせる時や質問する時にとても助かった経験があります。またこれも dominikg 氏の言葉ですが、「良い製品を作るには、何を追加しないかを決めるのが大事」という言葉が刺さりました。
「宣言的で合成可能なアーキテクチャ」の部分はみなさんお察しの通り Dan 先生の言葉ですが、React チームの精神を感じてよかったです。React チームは AI 時代にも React のアーキテクチャが生きると考えていることが伺えました。
